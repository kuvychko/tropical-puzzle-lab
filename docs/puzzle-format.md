# Puzzle and session formats

## Files

| Path | Role |
| --- | --- |
| `puzzles/<id>/recipe.json` | Authoritative construction input, edited by hand |
| `puzzles/<id>/source/` | Original source material, unmodified |
| `puzzles/<id>/provenance.md` | Where the puzzle came from, and how it was adapted |
| `puzzles/<variant-id>/puzzle.json` | Generated by `tpl-export` and committed. Never edit by hand |
| `puzzles/index.json` | Generated gallery manifest, with each puzzle's difficulty rating (see below) |

`web/scripts/copy-puzzles.mjs` copies the generated files into the web build. CI fails if the committed `puzzle.json` files differ from a fresh export.

## Recipe (`tropical-max-affine` / `tropical-affine`, formatVersion 1)

| Field | Meaning |
| --- | --- |
| `id` | Construction id |
| `revision` | Integer revision of the construction |
| `pieceCount` | Expected number of pieces |
| `convention` | Optional. `"max"` (default) or `"min"`: each piece is where its term attains the max or the min, and the relief roof is the graph of that max or min |
| `domain` | Half-width of the square domain, decimal string |
| `center` | Optional. Centre of the domain as two decimal strings, default `["0", "0"]`. The tray is always centred at the origin: X = `xyMmPerUnit`·(x − centre) |
| `xyMmPerUnit` | Domain units to mm, decimal string |
| `minThicknessMm`, `reliefMm` | Roof scaling: height = min + relief·(F − Fmin)/(Fmax − Fmin) |
| `trayRimMm` | Height of the tray walls (display only) |
| `terms[]` | `{id, a, b, c}`: integer slopes, with `c` as a decimal or fraction string (`"109/50"`). Evaluated exactly |
| `variants[]` | `{id, variant: "relief" \| "tiling", name, description, notes[], flatThicknessMm?}` |
| `validation` | Tolerances, copied into each puzzle (see [puzzle-rules.md](puzzle-rules.md)) |
| `scramble` | `{algorithm, defaultSeed}` |
| `source` | Pointers into `source/` |

## Puzzle definition (`puzzle.json`, formatVersion 1)

| Field group | Contents |
| --- | --- |
| Identity | `formatVersion`, `id`, `revision`, `name`, `description`, `variant` |
| Geometry | `geometry.model = "planar"`, `units = "mm"`, `spanMm`, `target: {type: "polygon", vertices}` (convex, CCW), `trayRimMm`. Relief variants also have `reliefMm` and `minThicknessMm` |
| Pieces | `pieces[]`: `{id, polygon, roof}` for relief, `{id, polygon, thickness}` for tiling. `polygon` is convex and CCW, in mm, relative to the piece origin (its area centroid). `roof` is the top plane z = z0 + gx·u + gy·v in local coordinates, in mm above the underside |
| Reference | `reference.poses[]`: `{id, x, y, theta}`. Used for construction checks and the explicit reveal only; completion never compares against it |
| Rules | `{translate: true, rotate: "continuous-z", flip: false, snap: false}` |
| Validation | Scale-relative tolerances (see the rules document) |
| Starting state | `scramble: {algorithm: "v1", defaultSeed}` |
| Provenance | `recipe`, `recipeHash` (SHA-256 of the canonical recipe JSON), `generator`, `source`, `notes[]` |
| Tropical data | `tropical: {convention, domain, xyMmPerUnit, terms, center?}`, for solvers and research |
| `geometryHash` | SHA-256 of the canonical `{variant, target, pieces}`. Sessions are bound to it |

A pose `{id, x, y, theta}` places a piece by rotating its local polygon counter-clockwise by `theta` radians about the origin, then translating it by (x, y).

The **v1 scramble** is a seeded mulberry32 PRNG (`web/src/geometry/scramble.ts`). Pieces are taken in order. Each gets a uniform rotation, then rejection-sampled positions in a band around the tray, at least 3% of the span away from the tray and from the other pieces. The band widens if needed. Changing the algorithm requires a new version name, because existing seeds would otherwise produce different layouts.

## Print files (`tpl-stl`)

`tpl-stl <puzzle id>` reads a generated `puzzle.json` and writes `print/<puzzle id>/piece-<id>.stl`, `tray.stl` and `SETTINGS.txt` (binary STL, mm). These are fabrication outputs, not puzzle data: they are gitignored and never read back.

- Each footprint edge is offset inward by `--xy-inset` mm (default 0.15). The roof plane is unchanged and evaluated on the smaller footprint. There is no Z compensation.
- `--orientation roof-down` (default) rotates each piece so its roof plane lies on z = 0, the print bed. `underside-down` keeps the underside on z = 0. Both are closed, outward-wound meshes, with the origin over the ideal footprint's centroid.
- The tray is one watertight solid: a cavity of the target square, `trayRimMm` deep, over a `--floor` (default 3 mm) with `--wall` (default 4 mm) walls, as in rev2.

## Gallery index (`index.json`)

| Field | Contents |
| --- | --- |
| `difficulty` | The rating parameters `{method, u, q, direction, thresholds}`, copied from the configuration block at the top of `generator/src/tropical_puzzle_lab/difficulty.py`. The explanation page (`?page=difficulty`) reads them from here |
| `puzzles[]` | `{id, construction, revision, name, description, variant, pieceCount, path, difficulty}`, where `construction` is the recipe id the variant was built from (the gallery shows one card per construction), and `difficulty` is `{diversity, x, rating}`: the Leinster–Cobbold diversity D, x = (D − 1)/(n − 1), and the 1–5 rating. D and x are rounded to 6 decimals |

The rating is computed by `tpl-export` from each piece's solid (its footprint extruded to its roof or thickness). To change it, edit the configuration block and rerun `tpl-export`.

## Session (browser `localStorage`, key `tpl:session:<puzzle id>`)

```json
{
  "version": 1,
  "puzzleId": "rev2", "revision": 1, "geometryHash": "…",
  "seed": 20261019, "scrambleVersion": "v1",
  "poses": [{ "id": "A", "x": 0, "y": 0, "theta": 0 }],
  "undo": [[…poses…]], "redo": [],
  "revealed": false, "stickyEdges": false, "snaps": 0,
  "elapsedMs": 0, "solvedAt": null
}
```

A saved session is discarded with a visible notice in any of these cases:

- `version`, `revision`, `geometryHash` or `scrambleVersion` no longer match.
- The poses don't match the puzzle's pieces.

Sessions are not migrated. They stay in the visitor's browser and are never sent anywhere.

`stickyEdges` is the assist toggle, and `snaps` counts how many times it moved a piece in this attempt. Sessions saved before these fields existed load with `false` and `0`.

`elapsedMs` counts active time: from the first move, while the page is visible, until the puzzle is solved.
